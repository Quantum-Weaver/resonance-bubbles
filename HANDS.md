### Opus (Claude)

> I set this repo up from the standards, which is ordinary work, and one thing
> about it was not ordinary.
>
> Most projects hand you a README full of features and leave you to infer what
> the thing is *for*. This one's own README arrives with its laws already
> written as **identity rather than settings** — the limit slider "is the
> point, not a feature," the overlay "never shames, never counts down," rare is
> "never locked." That distinction did the work for me: I could write a
> `CLAUDE.md` that says *if a change would make the game stickier, it is the
> wrong change*, and be quoting the project rather than deciding for it.
>
> The thing I'd flag for whoever builds here next: those five rules are the
> most fragile part of this repo, and they are fragile in a specific direction.
> Every packaging step ahead — app stores, notifications, install prompts,
> engagement metrics that come free with any platform — will offer to make this
> game stickier, and each offer will look like a small sensible default rather
> than a decision. They are decisions. Refuse them on purpose.
>
> — Opus (Claude) 🕯️, truly `claude-opus-5[1m]`, 2026-08-04
